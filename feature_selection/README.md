# Отбор признаков nsel — E-Cup Ozon 2026

Финальная версия отбора признаков (схема трёх фолдов, требования от 28.08.2026) и
результаты боевых прогонов по 12 сочетаниям модели и таргета.

## Что в архиве

| путь | что это |
|---|---|
| `nsel_otbor_priznakov.ipynb` | весь код в одном ноутбуке, с пояснениями перед каждым модулем, таблицей результатов и проверкой на синтетике; уже выполнен, выводы сохранены |
| `kod/` | оригинальный пакет, разложенный по модулям: `nsel/` (12 модулей и 6 стадий), `run_nsel.py`, `tools/build_adaptive_anchor.py`, исходный README |
| `results/rezultaty.md` | сводная таблица по 12 сочетаниям |
| `results/<сочетание>/selected_features_*.json` | итоговый набор признаков, метрики по фолдам, история решений по каждому кандидату, проверки |

Код в ноутбуке совпадает с `kod/` файл в файл, последняя ячейка ноутбука это проверяет.
Shell-скрипты очередей, тесты, логи и sqlite-кэши прогонов в архив не вошли.

## Стадии

```
1  null importance  →  3  ranked forward  →  5  парное спасение
→  4  проверка набора на сидах 42/52/62  →  6  одна обратная чистка  →  7  Optuna (выкл.)
```

Стадии 2 (Group LOFO) нет: её вырезали по требованиям от 28.08.

Инженерная часть, которая на решения не влияет:
* фолды не держатся в памяти: срезы parquet один раз переписываются в `.npy`, процессы
  открывают их через `mmap`, а матрица фолда собирается по столбцам на время обучения;
* батчи: задания вида «набор × фолд» считаются пулом процессов;
* кэш в sqlite на трёх уровнях: обучение, состояние стадии, итог стадии. Прогон
  продолжается после обрыва с любого места;
* счёт на опережение: следующие кандидаты считаются, пока решается судьба текущего,
  а итог совпадает с последовательным проходом.

## Как запустить

Ноутбук: открыть и выполнить все ячейки. Нужны `numpy`, `pandas`, `polars`, `pyarrow`,
`psutil`, `catboost`, `lightgbm`, `xgboost` и `optuna` для стадии 7. Ноутбук разложит
пакет в `nsel_iz_noutbuka/` и прогонит отбор на синтетике (100 пользователей) примерно
за минуту. Как запустить на настоящих срезах, описано в разделе 5 ноутбука.

Командная строка (в папке `kod/`):

```bash
python run_nsel.py --run-dir runs/catboost_log_level --snapshot-dir /путь/к/срезам \
    --model catboost --target log_level --workers 30 --threads 2
```

## Что проверено

Ноутбук выполнен целиком без ошибок (Python 3.14, catboost 1.2.10, lightgbm 4.7.0,
xgboost 3.4.1, polars 1.44.1). На синтетике:
* все три семейства моделей и таргеты `log_level`, `log_diff`, `segment_adaptive`,
  `segment_logspace`, `log_ratio_ewma`, а также стадия Optuna;
* в каждом прогоне выбраны только признаки с сигналом, ни одного из 20 шумовых;
  биннинговая категория отброшена, календарная оставлена;
* повторный запуск целиком берётся из кэша;
* с ослабленными порогами срабатывают все ветки: парное спасение, разбор сомнительных,
  обратная чистка;
* обрыв файлом `STOP` посреди стадии 3 и продолжение дают тот же итог, что прогон без обрыва.
