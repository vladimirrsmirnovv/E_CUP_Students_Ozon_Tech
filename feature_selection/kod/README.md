# Отбор признаков: схема трёх фолдов

Реализация требований коллеги от 28 августа 2026 (`PLAN_NEW.md`). Прежний
пятифолдовый отбор и вариант B заменены целиком.

## Что изменилось против прошлой схемы

| было | стало |
|---|---|
| пять фолдов, февраль 0.20 | три фолда: ноябрь 0.25, декабрь 0.35, январь 0.40 |
| стадия 2 Group LOFO | вырезана полностью |
| multiseed на каждый признак | сиды 42/52/62 проверяют набор целиком |
| обратная чистка каждые 5 добавлений | ровно одна, в самом конце |
| парное спасение всегда | выключено по умолчанию |
| один порог приёма | два пути: обычный и устойчивый малый выигрыш |
| шаг щупа 0.03 | 0.15 по замеру `research/REPORT.md` |

Январь больше не внешняя проверка: он участвует в отборе наравне с остальными.

## Порядок стадий

```
null importance -> ранжирование -> ranked forward selection
-> (опц.) парное спасение -> проверка набора на сидах
-> (опц.) подтверждение сомнительных -> ОДНА обратная чистка -> итог
-> (опц.) Оптуна на той же кросс-валидации
```

## Правило приёма

```
обычный путь:      выигрыш >= 0.00005 и улучшено фолдов >= 2
устойчивый путь:   выигрыш >= 0.00001 и улучшено фолдов == 3
```

Защита действует на обоих путях: просадка любого фолда не больше 0.002,
сегмента нулей 0.03, сегмента покупавших 0.005. Порог проверяется раньше
защиты, чтобы кандидат, не дотянувший до порога, не уходил в отчёт как
нарушитель защиты — иначе парное спасение теряло бы его из виду.

## Запуск

```bash
# быстрая проверка кода на настоящих данных, около минуты
python run_nsel.py --run-dir runs/smoke --smoke --users 3000 --features 30

# боевой прогон одного сочетания
python run_nsel.py --run-dir runs/catboost_log_level \
    --model catboost --target log_level --workers 30 --threads 2

# шесть сочетаний сразу

```

Переменные окружения `NSEL_*` дают то же самое для случаев, когда командную
строку задаёт чужой планировщик (см. `nsel/config.py:config_from_env`).

## Возобновление

Прогон переживает обрыв на любом месте любой стадии.

| уровень | что хранится | где |
|---|---|---|
| итерация | результат каждого отдельного обучения | таблица `iterations` |
| середина стадии | набор, курсор кандидатов, история решений | таблица `stage_state` |
| итог стадии | решение стадии целиком | таблица `stage_results` |

Ключ итерации — sha256 от отпечатка настроек, фолда, состава признаков,
параметров щупа, сида и режима перемешивания. Итог стадии дополнительно
привязан к отпечатку решающих настроек: сменился порог приёма или состав
фолдов — итоги стадий обесцениваются, а кэш обучений остаётся годным.

Остановить прогон, ничего не потеряв: `touch <run-dir>/STOP` либо SIGINT.

## Ускорение

Ускорения не меняют ни одного решения — они меняют только порядок счёта.

* **Опережающий счёт по рангу.** Отвергнутый кандидат не меняет состояние
  отбора, поэтому следующие по рангу кандидаты считаются заранее. На принятом
  очередь обрывается ровно там же, где оборвался бы последовательный проход.
  Проверено тестом: ширина 6 и ширина 1 дают одинаковый набор.
* **Непрерывная очередь.** Задания уходят в пул все сразу, барьера «дождаться
  пачку» нет: освободившийся процесс сразу берёт следующее.
* **Срезы в разделяемой памяти.** Каждый срез разложен в numpy матрицей
  «признак x строка» и открывается через `mmap`. Тридцать процессов делят одни
  страницы, а выбор подмножества признаков — это выбор строк матрицы.
* **Щуп с шагом 0.15.** Замер на сорока наборах: ранговая корреляция с шагом
  0.03 — 0.9998, десять лучших наборов совпали, счёт быстрее в 2.5 раза.
  Это единственное место, где мы сознательно отходим от его чисел.

## Кодирование категорий

CatBoost не тронут: у него своя обработка. Для XGBoost и LightGBM работает
ordered target encoding с эмпирико-байесовским сглаживанием, сила сглаживания
оценивается методом моментов. Все статистики берутся только из обучающей части
своего фолда; первый блок не кодируется, невиданная категория получает
глобальное среднее.

## Проверки

`nsel/checks.py` выполняется в конце каждого прогона и роняет его при
нарушении: контракт трёх фолдов, отсутствие Group LOFO, ровно одна обратная
чистка, multiseed на наборе, состояние парного спасения, непустой набор.
